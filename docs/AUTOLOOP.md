# AutoLoop — 自动循环开发框架

> 参考 RalphLoop 自动循环模式：大任务 → 小原子任务 → 反复迭代 → 拿到多个完整功能更新
> 核心原则：**每个原子任务都有明确通过标准，验证不过就不算完成**

---

## 一、核心机制

```
┌─────────────────────────────────────────────────────┐
│                   AutoLoop 循环引擎                    │
│                                                     │
│  大任务拆解 → 原子任务队列（每个带通过标准）            │
│  ┌─────────────────────────────────────────────┐    │
│  │  循环开始（每轮 = 1 个原子任务）               │    │
│  │  ┌─────────┐   ┌─────────┐   ┌─────────┐   │    │
│  │  │ 写代码   │ → │ 跑测试   │ → │ 修 Bug   │   │    │
│  │  └─────────┘   └─────────┘   └─────────┘   │    │
│  │        ↓ 通过标准验证                         │    │
│  │  ┌─────────────────────────────┐            │    │
│  │  │ 通过 → 提交 + 记录循环日志 → 下一轮       │    │
│  │  │ 失败 → 诊断 → 修复 → 重新验证            │    │
│  │  └─────────────────────────────┘            │    │
│  └─────────────────────────────────────────────┘    │
│                                                     │
│  循环终止：原子任务队列清空 或 达到轮次上限            │
└─────────────────────────────────────────────────────┘
```

---

## 二、原子任务拆解规则

### 拆解标准

| 规则 | 说明 |
|------|------|
| **单一职责** | 每个原子任务只做一件事（如"加 XP 实体"≠"加 XP 实体+等级计算+前端展示"） |
| **可独立验证** | 每个原子任务完成时有明确的验证命令（mvn test / vue-tsc / 构建） |
| **规模可控** | 一个原子任务约 30-100 行代码，超过则继续拆分 |
| **依赖有序** | 后端 → 前端 → 测试 → 文档，按依赖顺序排队列 |

### 通过标准（Acceptance Criteria）格式

每个原子任务必须声明：

```
原子任务: <名称>
目标: <一句话描述>
涉及文件: <文件列表>
通过标准:
  - [ ] 后端编译通过 (mvn compile)
  - [ ] 相关测试通过 (mvn test -Dtest=...)
  - [ ] 前端类型检查 0 错误 (vue-tsc --noEmit)
  - [ ] 前端构建成功 (vite build)
  - [ ] 功能可用（接口/页面真实调用成功）
回滚方式: <git revert 或删除文件的命令>
```

## 三、循环执行步骤（每轮）

### Step 1: 取任务
从原子任务队列取出队首任务，标记 in_progress。

### Step 2: 写代码
只改任务相关文件，不顺手重构。改完说明：
- 改了哪些文件
- 每个文件改了什么
- 为什么能覆盖任务目标

### Step 3: 跑测试
运行该任务的通过标准验证命令。**失败必须先解释原因**：
- 是本次改动导致的失败，还是既有历史失败
- 修复根因，不掩盖问题

### Step 4: 修 Bug
如果测试失败：
- 读错误 → 定位 → 最小改动修复 → 重新验证
- 禁止：删除测试、注释代码、绕过断言来"骗绿"

### Step 5: 验证通过
全部通过标准达成 → 标记该原子任务 completed。

### Step 6: 提交 + 记录
```
git add <相关文件>
git commit -m "loop: <原子任务名> - <一句话说明>"
```
向 `.github/loop-log.md` 追加一行循环日志：
```
| 2026-08-09 14:00 | 游戏化-后端 | 通过 | mvn test 35/35 | 说明 |
```

### Step 7: 下一轮
取下一个原子任务，重复 Step 1-6。队列清空则循环结束。

---

## 四、循环终止条件

| 条件 | 说明 |
|------|------|
| **正常终止** | 原子任务队列全部 completed |
| **卡死保护** | 同一任务连续失败 3 轮 → 停止并报告，等人工决策 |
| **轮次上限** | 单次会话最多 8 轮，防止无限循环 |

## 五、大任务拆解示例（本次循环目标）

### 大任务：游戏化体系（XP/等级/成就）

拆解为 5 个原子任务：

| # | 原子任务 | 通过标准 |
|---|----------|----------|
| A1 | 后端：UserXP 实体 + 等级枚举 | mvn compile 通过 |
| A2 | 后端：XP 累计服务（测评/登录/课程加 XP） | 相关单测通过 |
| A3 | 后端：等级计算 + 成就判定 API | 接口测试通过 |
| A4 | 前端：用户等级徽章组件 + 进度条 | vue-tsc 0 错误 + 构建通过 |
| A5 | 前端：个人中心 XP/成就展示 | 构建通过 + 页面数据联通 |

```markdown
# AutoLoop 循环日志

| 时间 | 原子任务 | 状态 | 验证结果 | 说明 |
|------|----------|------|----------|------|
| 2026-08-09 14:00 | 游戏化-A1 | ✅ 通过 | mvn compile | 实体+枚举完成 |
| 2026-08-09 14:20 | 游戏化-A2 | ✅ 通过 | test 36/36 | XP 累计服务完成 |
```

## 七、本框架的验证方式

框架本身是否有效，用以下标准衡量：
- [ ] 每个原子任务都有明确通过标准
- [ ] 每轮都有测试/检查命令在跑
- [ ] 测试失败能定位到根因并修复
- [ ] 每轮都有独立提交（可回滚）
- [ ] 循环日志有记录
- [ ] 一个会话内完成 ≥3 个完整功能更新
