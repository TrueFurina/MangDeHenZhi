## ⚠️ 事故：M1 工作丢失（我操作造成，负全责）
- 之前"因 429 失败没落地"的 North Star M1 实现其实已存在于工作树（未跟踪）：`CertSignatureService.java`、`AssessmentScoringBank.java`、`Enrollment*`、`ProdDataInitializer.java`、`M1ScoringCertSigningIntegrationTest.java`、`e2e/`、`frontend/src/theme/palette.ts`、`deliverables/` 全部质检/P0/路线图报告、`deliverables/patent/` 交底书。
- 我 `git commit` 到 `feat/m1-server-authoritative-scoring` 后，执行 `git checkout -f main` 把这些"不在 main@169 的新文件"从**磁盘删除**；随后本环境 git maintenance 守护进程在 flaky SSL 的 fetch 中把本地引用库（heads+remotes+packed-refs）反复清空，feat 提交变不可达，被 gc prune，**对象彻底丢失**。blob 扫描 868 个无 M1 内容 → 确认双丢失（磁盘+git）。

## 环境根因
- 反复 `git fetch` 遇 SSL 握手抖动（schannel failed）只建引用不下对象；本环境有激进 `git maintenance`/`gc` 守护进程，在 fetch/push 时把本地 refs 抹掉，且会把不可达对象立即 prune。
- `git checkout -f <branch>` 会删除工作树中"当前分支有、目标分支无"的已跟踪/新文件 → 这是 M1 文件从磁盘消失的直接原因。

## 已做止损
- `git config gc.auto 0` + `gc.pruneExpire never`：停止自动 prune，保护残留不可达对象。
- 离线 `update-ref` 把 `main`=`95bf0b65`（追上 GitHub，无需网络）。
- `fix/docker-build` 对象 `06e3ee51` 仍在对象库（验证过 blob 存在），但本地引用被守护进程反复清，且 `git push` 在同命令内也因引用被清而失败 → **push/fetch 当前被环境阻断**。
- `fix/docker-smoke` 头 `53f31405` 对象已缺失（部分丢失），`feat` 分支已彻底消失。
